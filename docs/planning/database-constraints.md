# Database Constraints

## Purpose And Status

This document is the explicit Stage 0 database constraint list for the initial
v1 persistence model in `erd.md`. It defines the constraints the Stage 1 Prisma
schema and initial migration must implement, or deliberately prove with a
transactional service invariant when PostgreSQL cannot enforce the rule with a
plain constraint.

The database remains PostgreSQL, all timestamps are UTC, every money value is an
integer Toman amount, and historical order data is retained instead of being
hard-deleted by normal application actions.

## Global Constraints

- Every table has a primary key, except pure join tables where the composite
  relationship is the primary key.
- UUID primary keys are generated by the database or the Prisma default and are
  never exposed as customer-facing order numbers.
- Required fields in the ERD are `NOT NULL`; optional fields are nullable only
  where this document or `erd.md` marks them as optional.
- Enum columns use controlled values only:
  - `UserRole`: `MANAGER`, `STAFF`
  - `OrderChannel`: `TABLE`, `TAKEAWAY`
  - `OrderState`: `OPEN`, `DELETED`
  - `PaymentStatus`: `UNPAID`, `PARTIALLY_PAID`, `PAID`
  - `DiscountKind`: `FIXED`, `PERCENTAGE`
  - `PaymentMethod`: `CASH`, `CARD_TERMINAL`, `CARD_TRANSFER`
- Monetary amount columns are integer Toman values and never floating-point
  values. Prices, discounts, settlement amounts, tender amounts, paid amounts,
  and balances must be non-negative unless a future ADR explicitly introduces a
  signed adjustment table.
- Quantities and minute durations must be whole integers. Sold quantities,
  selected settlement quantities, and positive duration configuration must be
  greater than zero. Derived elapsed/estimate totals may be zero only where the
  model states that zero means "none yet".
- Foreign keys preserve historical records. Normal application flows archive,
  deactivate, reverse, or logically delete records instead of physically
  deleting referenced business history.
- `createdAt`, `updatedAt`, `recordedAt`, `occurredAt`, `expiresAt`,
  `deletedAt`, `revokedAt`, and `archivedAt` are stored as UTC timestamps.
- Audit and idempotency JSON columns must contain safe operational data only;
  passwords, token material, cookies, and unnecessary personal data are never
  stored there.

## Table Constraints

### `users`

- Primary key: `id`.
- Required: `passwordHash`, `role`, `isActive`, `createdAt`, `updatedAt`.
- Checks:
  - `passwordHash` is not an empty string.
  - `role` is one of `MANAGER` or `STAFF`.
- Indexes:
  - Add role/active indexes only when measured Manager-user queries need them.

### `refresh_sessions`

- Primary key: `id`.
- Required: `userId`, `tokenHash`, `expiresAt`, `createdAt`.
- Optional: `revokedAt`.
- Checks:
  - `tokenHash` is not an empty string.
  - `expiresAt > createdAt`.
  - `revokedAt IS NULL OR revokedAt >= createdAt`.
- Indexes:
  - `userId`.
  - Add `tokenHash` uniqueness if session lookup uses the stored hash directly.

### `auth_events`

- Primary key: `id`.
- Required: `eventType`, `requestId`, `occurredAt`.
- Optional: `userId`.
- Checks:
  - `eventType` is not an empty string.
  - `requestId` is not an empty string.
- Indexes:
  - `userId`.
  - `occurredAt`.

### `categories`

- Primary key: `id`.
- Required: `name`, `displayOrder`, `isActive`.
- Optional: `archivedAt`.
- Checks:
  - `name` is not an empty string.
  - `displayOrder >= 0`.
  - `archivedAt IS NULL OR isActive = false`.
- Indexes:
  - `(isActive, displayOrder)`.

### `products`

- Primary key: `id`.
- Required: `categoryId`, `name`, `priceAmount`,
  `preparationDeadlineMinutes`, `displayOrder`, `isActive`, `isAvailable`.
- Optional: `archivedAt`.
- Checks:
  - `name` is not an empty string.
  - `priceAmount >= 0`.
  - `preparationDeadlineMinutes > 0`.
  - `displayOrder >= 0`.
  - `archivedAt IS NULL OR isActive = false`.
- Indexes:
  - `(categoryId, isActive, isAvailable, displayOrder)`.

### `product_images`

- Primary key: `id`.
- Unique: `productId`.
- Required: `productId`, `storageKey`, `altText`.
- Checks:
  - `storageKey` is not an empty string.
  - `altText` is not an empty string.

### `option_groups`

- Primary key: `id`.
- Required: `name`, `isActive`.
- Checks:
  - `name` is not an empty string.

### `product_option_groups`

- Primary key: `(productId, optionGroupId)`.
- Required: `productId`, `optionGroupId`, `displayOrder`.
- Checks:
  - `displayOrder >= 0`.

### `options`

- Primary key: `id`.
- Required: `optionGroupId`, `name`, `priceAmount`, `isActive`,
  `isAvailable`, `displayOrder`.
- Optional: `archivedAt`.
- Checks:
  - `name` is not an empty string.
  - `priceAmount >= 0`.
  - `displayOrder >= 0`.
  - `archivedAt IS NULL OR isActive = false`.
- Indexes:
  - `(optionGroupId, isActive, isAvailable, displayOrder)`.

### `cafe_tables`

- Primary key: `id`.
- Required: `name`, `seatingLimitMinutes`, `displayOrder`, `isActive`.
- Optional: `archivedAt`.
- Checks:
  - `name` is not an empty string.
  - `seatingLimitMinutes > 0`.
  - `displayOrder >= 0`.
  - `archivedAt IS NULL OR isActive = false`.
- Indexes:
  - `(isActive, displayOrder)`.

### `orders`

- Primary key: `id`.
- Unique: `orderNumber`.
- Required: `orderNumber`, `createdById`, `channel`, `state`,
  `paymentStatus`, `version`, `discountAmount`, `subtotalAmount`,
  `totalAmount`, `paidAmount`, `balanceAmount`,
  `estimatedPreparationMinutes`, `createdAt`, `updatedAt`.
- Optional: `tableId`, `discountKind`, `discountValue`, `discountReason`,
  `tableSeatingLimitSnapshotMinutes`, `estimatedTableReleaseAt`, `deletedById`,
  `deletedAt`, `deletionReason`.
- Checks:
  - `orderNumber` is not an empty string.
  - `version >= 1`.
  - `subtotalAmount >= 0`.
  - `discountAmount >= 0`.
  - `totalAmount >= 0`.
  - `paidAmount >= 0`.
  - `balanceAmount >= 0`.
  - `estimatedPreparationMinutes >= 0`.
  - `discountKind IS NULL` iff `discountValue IS NULL`.
  - When `discountKind = 'PERCENTAGE'`, `discountValue BETWEEN 1 AND 100`.
  - When `discountKind = 'FIXED'`, `discountValue > 0`.
  - `discountAmount <= subtotalAmount`.
  - `totalAmount = subtotalAmount - discountAmount`.
  - `paidAmount <= totalAmount`.
  - `balanceAmount = totalAmount - paidAmount`.
  - `channel = 'TABLE'` iff `tableId IS NOT NULL`.
  - `channel = 'TAKEAWAY'` iff `tableId IS NULL`.
  - `channel = 'TABLE'` iff `tableSeatingLimitSnapshotMinutes IS NOT NULL`.
  - `channel = 'TAKEAWAY'` iff `tableSeatingLimitSnapshotMinutes IS NULL`.
  - `tableSeatingLimitSnapshotMinutes IS NULL OR tableSeatingLimitSnapshotMinutes > 0`.
  - `estimatedTableReleaseAt IS NULL` iff `channel = 'TAKEAWAY'`.
  - `state = 'DELETED'` iff `deletedAt IS NOT NULL AND deletedById IS NOT NULL`.
  - `state = 'OPEN'` iff `deletedAt IS NULL AND deletedById IS NULL`.
  - `paymentStatus = 'UNPAID'` requires `paidAmount = 0`.
  - `paymentStatus = 'PAID'` requires `paidAmount = totalAmount AND balanceAmount = 0`.
  - `paymentStatus = 'PARTIALLY_PAID'` requires `paidAmount > 0 AND paidAmount < totalAmount`.
- Indexes:
  - `(tableId, state)`.
  - `(state, paymentStatus)`.
  - `createdAt`.

### `order_items`

- Primary key: `id`.
- Required: `orderId`, `productId`, `productNameSnapshot`,
  `basePriceSnapshot`, `preparationDeadlineSnapshotMinutes`, `quantity`,
  `discountAmount`, `lineTotalAmount`, `displayOrder`.
- Optional: `note`.
- Checks:
  - `productNameSnapshot` is not an empty string.
  - `basePriceSnapshot >= 0`.
  - `preparationDeadlineSnapshotMinutes > 0`.
  - `quantity > 0`.
  - `discountAmount >= 0`.
  - `lineTotalAmount >= 0`.
  - `displayOrder >= 0`.
- Indexes:
  - `(orderId, displayOrder)`.
  - `productId`.

### `order_item_options`

- Primary key: `id`.
- Required: `orderItemId`, `optionId`, `optionNameSnapshot`, `priceSnapshot`,
  `quantity`.
- Checks:
  - `optionNameSnapshot` is not an empty string.
  - `priceSnapshot >= 0`.
  - `quantity > 0`.
- Indexes:
  - `orderItemId`.

### `payment_settlements`

- Primary key: `id`.
- Unique: `(orderId, idempotencyKey)`.
- Required: `orderId`, `recordedById`, `idempotencyKey`, `totalAmount`,
  `recordedAt`.
- Checks:
  - `idempotencyKey` is not an empty string.
  - `totalAmount > 0`.
- Indexes:
  - `recordedById`.

### `settlement_allocations`

- Primary key: `id`.
- Required: `settlementId`, `orderItemId`, `quantity`, `amount`.
- Checks:
  - `quantity > 0`.
  - `amount > 0`.
- Indexes:
  - `orderItemId`.

### `payments`

- Primary key: `id`.
- Required: `settlementId`, `method`, `amount`, `recordedAt`.
- Optional: `reference`.
- Checks:
  - `amount > 0`.
  - `method = 'CARD_TRANSFER'` allows `reference` to be null or a non-empty string.
  - `method = 'CARD_TERMINAL'` requires `reference IS NULL`.
  - `method = 'CASH'` requires `reference IS NULL`.
- Indexes:
  - `settlementId`.

### `settlement_reversals`

- Primary key: `id`.
- Unique: `settlementId`.
- Required: `settlementId`, `recordedById`, `reason`, `recordedAt`.
- Checks:
  - `reason` is not an empty string.
- Indexes:
  - `recordedById`.

### `idempotency_records`

- Primary key: `id`.
- Unique: `(actorId, operation, key)`.
- Required: `actorId`, `operation`, `key`, `requestFingerprint`,
  `responseStatus`, `resultSnapshot`, `expiresAt`, `createdAt`.
- Checks:
  - `operation` is not an empty string.
  - `key` is not an empty string.
  - `requestFingerprint` is not an empty string.
  - `responseStatus BETWEEN 100 AND 599`.
  - `expiresAt > createdAt`.
- Indexes:
  - `expiresAt`.

### `audit_logs`

- Primary key: `id`.
- Required: `requestId`, `operation`, `entityType`, `entityId`, `occurredAt`.
- Optional: `actorId`, `beforeSnapshot`, `afterSnapshot`, `reason`.
- Checks:
  - `requestId` is not an empty string.
  - `operation` is not an empty string.
  - `entityType` is not an empty string.
  - `entityId` is not an empty string.
- Indexes:
  - `(entityType, entityId)`.
  - `occurredAt`.

### `cafe_settings`

- Primary key: `id`.
- Required: `defaultTableSeatingLimitMinutes`, `updatedAt`.
- Optional: `updatedById`.
- Singleton rule:
  - The table may contain at most one row. Implement this with a stable
    singleton key, fixed primary-key value, or an equivalent unique expression in
    the initial migration.
- Checks:
  - `defaultTableSeatingLimitMinutes > 0`.

## Transactional Invariants

The following rules are part of the database contract but require transactional
service logic, row locks, deferred checks, triggers, or integration tests because
they span multiple rows.

- An order must have at least one `OrderItem` after an order creation
  transaction commits.
- An order's `subtotalAmount` equals the sum of its order item pre-discount
  totals.
- An order's `estimatedPreparationMinutes` equals the maximum
  `OrderItem.preparationDeadlineSnapshotMinutes` across its current items.
- A table order's `estimatedTableReleaseAt` equals `createdAt +
tableSeatingLimitSnapshotMinutes + estimatedPreparationMinutes`.
- Order content, discount, and table assignment updates are accepted only while
  `state = 'OPEN'` and `paymentStatus = 'UNPAID'`.
- Stale order updates are rejected through a compare-and-swap check on
  `Order.version`.
- Creating an order with an idempotency key inserts or replays one
  `IdempotencyRecord` in the same transaction as the order write.
- A settlement has at least one `SettlementAllocation` and at least one
  `Payment` after the settlement transaction commits.
- Every allocation in a settlement belongs to an order item from the same order
  as the settlement.
- Active, non-reversed settlement allocations for an `OrderItem` never exceed
  `OrderItem.quantity`.
- A settlement's `totalAmount` equals the sum of its allocation amounts.
- Tender amounts for one settlement sum exactly to
  `PaymentSettlement.totalAmount`.
- Recording a settlement, inserting its allocations and tenders, updating order
  paid/balance/status fields, incrementing `Order.version`, and writing audit
  entries happen atomically.
- A settlement reversal applies to the whole settlement, has exactly one
  `SettlementReversal` row, recalculates the order paid/balance/status fields,
  increments `Order.version`, and writes an audit entry atomically.
- Posted settlements, tenders, allocations, reversals, and audit rows are never
  updated or deleted by normal application actions.
- Logical order deletion writes `state = 'DELETED'`, `deletedById`, `deletedAt`,
  optional `deletionReason`, increments `Order.version`, and writes an audit
  entry atomically.
- Manager-only operations are enforced in application authorization and are
  covered by API and integration tests; the database records the actor for
  auditability but does not make role-based write decisions.
